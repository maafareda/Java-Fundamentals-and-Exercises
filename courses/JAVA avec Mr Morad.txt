PART 1 : POO

- POO : Programmation Orientée Objet

- La POO se base sur 4 principes :

    1- Encapsulation : la sécurité (les données sont protégées de l'extérieur, seules les méthodes qui ont le droit peuvent communiquer avec les attributs, et pour communiquer on utilise les méthodes. Les méthodes jouent le rôle d'interface).

    2- Héritage : la réutilisation.

    3- Polymorphisme : l'extensibilité (il doit être présent avec l'héritage. C'est la modification ou la mise à jour sans revenir au code, juste en faisant l'appel).

    4- Abstraction : c'est lorsqu'on fait une classe abstraite, c'est-à-dire qu'elle ne peut pas être instanciée. Elle sert pour l'héritage.


LES CLASSES ABSTRAITES

    - Une classe qui contient au moins une méthode abstraite.

    - Une classe qui hérite d'une classe abstraite doit obligatoirement redéfinir toutes les méthodes abstraites de sa classe mère.

    - Une classe qui refuse de redéfinir les méthodes abstraites de sa classe mère doit être abstraite.

    - Une classe abstraite n'est pas instanciable.

    - La notion en POO sert à exiger un protocole (un contrat de travail pour les classes filles) pour un but organisationnel.

    - On doit redéfinir toutes les méthodes, garder les mêmes types.


JAVA : HÉRITAGE

    - En héritage, si une classe hérite d'une classe, elle peut redéfinir la méthode dont elle hérite.

    - En Java, il n'y a pas d'héritage multiple, ce qui veut dire qu'une classe hérite d'une seule classe.


QU'EST-CE QU'UNE INTERFACE ?

    - Une interface, avant Java 8 (2014), était purement abstraite (ça veut dire que toutes ses méthodes étaient abstraites). Mais après Java 8, cette notion a changé.

    - Java 8 : l'interface peut contenir des méthodes concrètes (static, default, private).

    - Une interface contient des attributs final static.


EN RÉSUMÉ :

    Interface :

        - Une interface peut contenir les attributs et les méthodes sans définition, mais elle a l'avantage qu'elle peut être implémentée par plusieurs classes à la fois.

    Classe abstraite :

        - Une classe qui a la possibilité d'avoir des attributs, des méthodes avec une définition ou sans. Mais il y a le problème du diamant.


    - En héritage, pour le constructeur, on ne fait pas l'ancienne méthode, on utilise super(attribut mère) + this.attribut fille.

    - Une classe qui contient une méthode abstraite doit être une classe abstraite.

    - Interface : les méthodes n'ont pas besoin de code, c'est final, et même les attributs, mais ceux-ci sont final. Il faut les faire private ou static ou par défaut.

        public default void ...() { ...code... }

    - Redéfinition : on ne doit pas changer les attributs.


LES EXCEPTIONS

    - try : on écrit le code à exécuter et, s'il rencontre une erreur, il passe à finally.

    - On écrit les codes susceptibles de provoquer une erreur.

    - catch : quand il trouve une erreur, il entre dans le catch et il arrête.

    - finally : toujours exécuté, même s'il trouve une erreur.


    try : J'essaie d'exécuter un code qui peut planter.

    catch : Si ça plante avec une certaine erreur, je fais ceci au lieu de laisser le programme s'arrêter.

    finally (optionnel) : Dans tous les cas (plante ou pas), je fais ce nettoyage (ex. fermer un fichier).


    - On peut faire un try avec plusieurs catch. Les catch où on fait les exceptions vont être choisis automatiquement par Java. On peut même faire des classes d'exception.
