3. Gestion des exceptions

Une exception est une erreur qui se produit pendant l’exécution d’un programme.

Par exemple :

Java
int a = 10;
int b = 0;

System.out.println(a / b);

Ici, on essaie de faire 10 / 0, ce qui provoque une exception :

ArithmeticException

Pour éviter que le programme s’arrête brutalement, on peut gérer l’exception.

3.1 Exceptions vérifiées et non vérifiées

Il existe principalement 2 types.

1. Checked Exceptions

Ce sont des exceptions que Java oblige le programmeur à gérer ou à déclarer.

Exemple :

Java
import java.io.FileReader;
import java.io.IOException;

public class Main {
    public static void main(String[] args) {

        try {
            FileReader fichier = new FileReader("test.txt");
        } catch (IOException e) {
            System.out.println("Erreur avec le fichier");
        }
    }
}

IOException est une Checked Exception.

Pourquoi ?

Parce que Java sait qu'une opération comme ouvrir un fichier peut échouer :

  • fichier inexistant

  • problème de permission

  • problème de lecture...

Donc Java nous oblige à prévoir le problème.

Exemples :

  • IOException

  • SQLException

2. Unchecked Exceptions

Ce sont des exceptions que Java ne nous oblige pas à gérer.

Elles apparaissent généralement à cause d'une erreur dans le programme.

Exemple :

Java
int age = -5;

if (age < 0) {
    throw new IllegalArgumentException("Age invalide");
}

IllegalArgumentException est une Unchecked Exception.

Autres exemples :

Java
int x = 10 / 0;

→ ArithmeticException

Java
String nom = null;
System.out.println(nom.length());

→ NullPointerException

Donc :

TypeJava oblige à gérer ?Exemple
CheckedOuiIOException
UncheckedNonIllegalArgumentException
UncheckedNonNullPointerException
UncheckedNonArithmeticException

À retenir

Checked :

"Java me demande de prévoir cette erreur."

Unchecked :

"Java ne m'oblige pas, mais l'erreur peut arriver pendant l'exécution."

3.2 Gestion globale des exceptions

La gestion globale des exceptions signifie qu'on centralise la gestion des erreurs au lieu de mettre le même try-catch partout.

Sans gestion globale

Imaginons une application avec plusieurs méthodes :

Java
try {
    ajouterClient();
} catch (Exception e) {
    System.out.println("Erreur");
}

Puis :

Java
try {
    ajouterLivre();
} catch (Exception e) {
    System.out.println("Erreur");
}

Puis :

Java
try {
    supprimerLivre();
} catch (Exception e) {
    System.out.println("Erreur");
}

On répète le même code plusieurs fois.

Avec une gestion globale

On peut avoir un endroit central qui s'occupe des exceptions.

L'idée est :

Erreur
   ↓
Exception
   ↓
Gestion globale
   ↓
Réponse standard

Par exemple, dans une application web Java, au lieu de gérer chaque erreur séparément, on peut avoir un système qui intercepte les exceptions et retourne toujours une réponse organisée :

Erreur : utilisateur inexistant
Code : 404
Message : Utilisateur non trouvé

Cela permet de :

  • éviter la répétition du même code

  • centraliser la gestion des erreurs

  • avoir des messages standardisés

  • rendre le programme plus facile à maintenir

Exemple très simple

Java
try {
    int resultat = 10 / 0;
}
catch (Exception e) {
    System.out.println("Une erreur est survenue");
}

Ici :

Java
catch (Exception e)

récupère l'exception et permet au programme de continuer de manière contrôlée.

🧠 Résumé

EXCEPTIONS
│
├── Checked Exceptions
│   └── Java oblige à gérer/déclarer
│       Exemple : IOException, SQLException
│
└── Unchecked Exceptions
    └── Java n'oblige pas à gérer
        Exemple : IllegalArgumentException
                   NullPointerException
                   ArithmeticException

Gestion globale = mettre la gestion des erreurs dans un endroit central pour éviter de répéter le même try-catch partout.
